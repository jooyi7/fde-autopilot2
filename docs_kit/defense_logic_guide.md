## 💡 만능 3문장 답변 공식 (결론 $ightarrow$ 코드/데이터 근거 $ightarrow$ 예외 방어 및 한계)
모든 서술형 질문은 문항당 5분 안에 직접 타이핑해야 하므로 **3~4문장(약 200~300자)**의 두괄식 구조로 간결하고 명확하게 작성한다.

### [유형 1] "특정 기능을 어떻게 구현했는가? 왜 그렇게 설계했는가?"
- **1문장 (핵심 구조):** 해당 기능은 연산과 판정의 정확성을 보장하기 위해 `[파일명/함수명]`의 결정론적 코어 로직과 UI/AI 해석 계층을 분리하여 구현했습니다.
- **2문장 (구체적 동작):** 입력 데이터에서 `[필드명]`을 파싱한 뒤, 설정 객체(`CONFIG`)에 정의된 `[기준값/조건]`을 기준으로 상태를 판별하여 일관된 결과가 도출되도록 처리했습니다.
- **3문장 (예외 방어):** 특히 결측치나 경계값 입력 시 런타임 오류가 발생하지 않도록 사전 검증 및 Fallback 로직을 추가하여 안정성을 확보했습니다.

### [유형 2] "제공된 데이터의 문제점(결측치/중복/충돌)을 어떻게 처리했는가?"
- **1문장 (탐지 내용):** 초기 데이터 프로파일링 과정에서 `[파일명/컬럼명]`에 결측치(또는 중복/센티널 이상치) 및 포맷 불일치 데이터가 존재하는 것을 확인했습니다.
- **2문장 (처리 방식 및 근거):** 원본 데이터를 임의로 삭제하면 전체 통계가 왜곡될 수 있어(또는 실무자 에이전트와의 DM 협의를 거쳐), 파서 단에서 이를 별도의 예외 플래그(`INVALID`)로 분리하고 유효 데이터만 핵심 지표 집계에 반영했습니다.
- **3문장 (화면 반영):** 분리된 이상 데이터는 실무자가 원인을 추적할 수 있도록 화면 내 별도 상태 배지 및 필터로 확인할 수 있게 구성했습니다.

### [유형 3] "질문의 전제와 내 실제 구현이 다를 때" (가이드라인 8장 명시 사항)
- **가이드라인 핵심 규칙:** *"질문의 전제와 실제 구현이 다르면 차이를 밝히고 본인의 작업을 설명하세요."*
- **답변 템플릿:** "문항에서는 A 방식을 전제하고 있으나, 실제 구현에서는 제한된 시간 내 데이터 정합성과 실행 안정성을 높이기 위해 B 방식(`[실제 구현한 파일명/함수명]`)을 선택하여 구현했습니다. 이를 통해 외부 의존성이나 런타임 오류 없이 즉각적인 판정과 화면 렌더링을 달성했으며, 향후 요구사항 확장 시 A 방식으로 쉽게 교체할 수 있도록 인터페이스 모듈을 분리해 두었습니다."

### [유형 4] "현재 구현의 한계점과 개선 방향은 무엇인가?"
- **답변 템플릿:** "현재 구현은 주어진 데이터셋 규모에서 정확한 판정과 빠른 응답을 보장하기 위해 인메모리 파싱 및 동기식 규칙 평가 기반으로 작성되었습니다. 만약 실제 운영 환경에서 대용량 데이터가 실시간으로 유입된다면 데이터베이스 인덱싱과 서버사이드 페이지네이션(또는 비동기 메시지 큐)을 도입하여 처리량과 메모리 안정성을 고도화해야 합니다."
