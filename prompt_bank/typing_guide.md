## 🏆 공식 1: "아키텍처 설계 의도와 AI/코드 역할 분담 근거를 설명하시오"

### [타이핑 모범 답안 (그대로 보고 치기)]
본 과제에서는 판정의 일관성과 수치 연산의 무결성을 100% 보장하기 위해 결정론적 코어(80%)와 유연한 AI 해석(20%)을 물리적으로 분리하여 설계했습니다.
구체적으로 src/core/rules.js의 evaluateCoreRules 함수에서 임계치 비교, 정규식 탐지, 수율 및 점수 계산을 순수 함수로 고정 처리하고, src/ai/reporter.js의 generateInsightWithFallback 함수는 코어가 확정한 JSON 판정 결과만을 입력받아 자연어 요약과 조치 가이드를 생성하도록 제한했습니다.
만약 산술 계산이나 합불 판정까지 LLM에 맡길 경우 환각 현상이나 응답 지연으로 인해 현장 의사결정이 흔들리는 치명적 위험이 발생하기 때문입니다.
아울러 상단에 정상, 경고, 위반 3종 골든 샘플 버튼을 두어 경계 조건을 즉시 검증했고, AI API 타임아웃이나 장애 시에도 0.1초 내로 결정론 코어의 표준 리포트를 반환하는 Fallback 안전장치를 구현해 무중단 가용성을 확보했습니다.

## 🏆 공식 2: "현재 코드의 한계점(약점)과 실제 현장 도입 시 리스크 및 개선 계획을 서술하시오"

### [타이핑 모범 답안 (1등 만점 3단 논법)]
1단계(구체적 약점 지목): 제한된 시간 내에 핵심 요구사항(In-Scope)의 End-to-End 관통과 판정 정확도에 집중하느라, 현재 src/core/rules.js의 evaluateCoreRules 함수는 단일 스레드 인메모리 동기 순회 방식으로 동작하며, src/ai/reporter.js의 generateInsightWithFallback 함수는 API 에러 시 즉시 Fallback 텍스트로 우회할 뿐 정밀한 재시도 큐(Retry Queue) 제어가 부재하다는 한계가 있습니다.
2단계(현장 파급 위험): 실제 공정이나 현업의 교대 시간대에 수만 건 이상의 대용량 로그가 동시에 유입될 경우 브라우저 메인 스레드 블로킹으로 화면이 멈추거나, 일시적인 API 트래픽 폭주 시 심층 AI 원인 추론이 생략되어 담당자의 의사결정이 지연될 위험이 있습니다.
3단계(검증 및 개선 계획): 이를 해결하기 위해 우선 1만 건 이상의 더미 부하 스크립트를 주입하여 처리 지연(Latency)과 메모리 점유율이 급증하는 정확한 데이터 크기 임계점을 먼저 계측(검증)하겠습니다. 단기적으로는 동일 판정 패턴에 대해 AI 응답을 재사용하는 인메모리 해시 캐싱과 로컬 스토리지 이력 저장을 적용하고, 장기적으로는 대용량 파싱과 코어 연산을 Web Worker 및 백엔드 비동기 메시지 큐 구조로 분리하여 고도화할 계획입니다.

## 🏆 공식 3: "데이터 검증 및 예외 상황(결측치, 경계값, 비정상 입력)을 어떻게 방어했는지 설명하시오"

### [타이핑 모범 답안]
현장 데이터에 빈번하게 섞여 들어오는 결측치(Null, NaN, 빈 문자열)와 경계값으로 인한 런타임 크래시를 원천 차단하기 위해 2중 방어 파이프라인을 구축했습니다.
먼저 입구인 src/data/samples.js의 sanitizeAndParseInput 파서에서 유효하지 않은 타입이나 결측값을 사전에 필터링하고 결측 건수를 별도 카운트하여 코어로 전달했습니다.
이어서 src/core/rules.js의 evaluateCoreRules 함수에서 정상 범위, 상하한 임계치 근접 경고(Warning) 구간, 스펙 이탈 위반(Violation) 구간을 명확한 수식으로 분기 처리했습니다.
최종적으로 deterministic_harness 테스트 스크립트를 통해 정상, 경계값, 위반, 파괴적 Null 입력, AI 장애 시뮬레이션까지 총 5가지 케이스가 모두 에러 없이 통과함을 터미널 단위 테스트로 검증했습니다.

## 🏆 공식 4: 질문의 전제가 내 실제 구현과 다를 때 대처법 (응시 가이드 8장 명시 원칙)

### [타이핑 모범 답안]
문항에서는 [질문이 전제한 기능/방식]을 기준으로 질문하셨으나, 본 구현에서는 제한된 180분 내에 핵심 비즈니스 병목(In-Scope)의 완벽한 동작과 오차 0% 판정을 보장하기 위해 SPEC.md의 Out-of-Scope 합의에 따라 의도적으로 src/core/rules.js 중심의 경량 아키텍처로 구현했습니다.
복잡한 외부 의존성 대신 순수 함수 기반의 결정론 코어와 3종 골든 샘플 프리셋 구조를 택함으로써 런타임 에러 가능성을 제거하고 응답 속도를 1초 이내로 단축했으며, 향후 운영 단계에서 앞서 작성한 HANDOFF.md의 로드맵에 따라 해당 기능을 확장할 수 있도록 모듈 인터페이스를 분리해 두었습니다.
